# 阶段门禁细则

## 立项门禁

- 明确游戏玩法、目标用户、核心循环、单局时长。
- 判断是否属于平台高风险或暂不接入类型：棋牌、捕鱼、网赚、涉赌、外部游戏盒子、低质文字类、纯 UGC 等。
- 明确主体类型：个人或企业。
- 明确是否需要内购、广告、虚拟支付、实物奖励、现金或话费活动。

## 资质门禁

- 创建小游戏前：完成主体认证；如需创建小游戏，主体认证为必要条件。
- 基础信息：名称、图标、简介、详细介绍、软著、版号、IP 资质按需完善。
- 名称、软著、版号保持一致；修改名称、软著、版号可能触发重新备案和 ICP。
- 无版号小游戏需关注小游戏备案；所有小游戏均需关注 ICP 核准。

## 开发门禁

- 确定技术路线：普通小游戏、Unity/团结、Cocos、Laya、Egret、Godot。
- 跑通开发者工具、测试版本上传和真机扫码体验。
- 配置 `game.json`、基础库最低版本、屏幕方向、网络超时。
- 涉及新 API 时使用 `tt.canIUse` 或 C# `CanIUse` 做兼容判断。

## 平台能力门禁

- 客服能力：内购或用户投诉场景必须重点检查。
- 敏感词：凡有文字输入、昵称、评论、UGC 文本，应接入文本安全/敏感词处理。
- 侧边栏复访：新游首发和版本更新有拒审风险，应尽早规划接入。
- 搜索关键词和分享内容：上线前配置，不要发布后再补。

## 提审门禁

- 上传测试版本并扫码体验。
- 按自审标准检查：黑屏、白屏、闪退、按钮无响应、授权拒绝后无法进入、支付调起异常、广告遮挡、分享诱导、录屏异常、敏感词过滤、iOS 虚拟支付限制。
- 提交审核时准备三张游戏内截图。
- 若要灰度，提交审核时不要提前勾选自动发布。

## 上线门禁

- 版本审核通过。
- ICP 核准和小游戏备案路径无阻塞。
- 搜索关键词、分享内容、客服入口、数据指标、商业化配置已完成或有明确暂缓说明。
- 上线后进入数据复盘，不以“发布成功”作为项目完成。

## 运营门禁

- 跟踪活跃用户、新增用户、打开次数、分享次数、录屏成功发布率、留存、平均下载耗时、平均加载耗时、平均帧率、重启率、JS 加载错误率、取消率。
- 巡检期重点关注用户体验问题和审核回复整改。
- 商业化后建立收入结算、确认账单、发票、提现流程。
